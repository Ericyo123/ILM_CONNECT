# Project Guidelines & Rules

## Browser and Preview Interactions
Do not automatically open, launch, or refresh the browser preview after making code changes. Make the requested changes directly in the code, and only run the necessary checks. Do not start a preview server or open the browser unless I explicitly ask you to preview or test the UI. Prioritize fast execution and avoid unnecessary browser interactions.

## Autonomous UI/UX Design and Quality Assurance
For every frontend design or UI implementation task, work autonomously until the result meets a professional quality standard.

### Design Standards (UI/UX Pro Max)
- Before implementing any UI, establish the visual direction, typography, spacing scale, color palette, and component design system.
- Prioritize premium aesthetics, strong visual hierarchy, responsive layouts, precise alignment, and consistent spacing.
- Avoid generic AI-generated layouts, unnecessary gradients, excessive rounded cards, and decorative elements without purpose.
- Preserve existing functionality and inspect the existing code before making changes.
- Ensure the design is responsive across mobile, tablet, and desktop.

### Line Spacing & Typography Discipline
- Headings must use calibrated line-height (`leading-[1.12]` to `leading-[1.2]`).
- Never insert artificial vertical margins or bloated gaps between individual lines of a heading. Use natural line breaks (`<br />`) with an exact `line-height` so text breathes naturally without looking cramped or bloated.
- Screen all content for typos, clarity, conciseness, and dignified tone.

## Git & Deployment Rules
- Do NOT push to GitHub or any remote repository until explicitly instructed by the user. Keep all commits local.
